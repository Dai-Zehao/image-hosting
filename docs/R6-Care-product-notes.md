# R6 Care 产品与后端建议

## 后端选择

Supabase 很适合 R6 Care 的 MVP 和早期商业化：它提供 PostgreSQL、Auth、Row Level Security、Storage、Edge Functions 和 Realtime，健康记录这种“用户私有数据 + 时间序列查询 + 统计聚合”的场景与 Postgres 很匹配。

如果后续要做医疗级合规、医院系统对接、可穿戴设备大规模流式数据，建议拆出专门服务：Postgres 保存业务数据，队列处理设备同步，ClickHouse/TimescaleDB 做高频指标分析。但当前阶段不需要过早复杂化。

## 热量公式

主界面使用 Mifflin-St Jeor 公式：

```text
男性 BMR = 10 * 体重kg + 6.25 * 身高cm - 5 * 年龄 + 5
女性 BMR = 10 * 体重kg + 6.25 * 身高cm - 5 * 年龄 - 161
TDEE = BMR * 活动系数
```

只用“身高 + 性别”无法准确估算每日热量，至少还需要体重和年龄。R6 Care 可以把身高、性别作为 onboarding 的基础字段，但计算页应要求补齐年龄、体重和活动水平。

## 核心功能

- 档案：性别、生日、身高、活动水平、时区、每日热量与宏量营养目标。
- 卡路里测算：BMR、TDEE、BMI、目标热量差。
- 体重记录：每日体重、体脂、腰围、备注，支持趋势图。
- 食物计算：自定义食材库、餐次、餐次条目，按克数折算热量、蛋白质、脂肪、碳水。
- 每日目标：允许每天覆盖目标，适配训练日和休息日。
- 健康目标：减脂、维持、增肌、自定义目标，记录目标体重与计划周期。
- 饮水记录：简单但高频，适合做成首页入口。

## 下一步建议

1. 接入 Supabase Auth，注册后自动创建 `user_profiles`。
2. 添加 `daily_nutrition_summary` 的前端查询，驱动首页今日摄入。
3. 为食物库增加全文搜索或拼音搜索。
4. 增加条形码扫描与常见食物导入。
5. 增加 AI 食物识别，但要保留用户确认流程，避免误算。
6. 增加“健康免责声明”：结果用于生活管理，不替代医生或营养师建议。
